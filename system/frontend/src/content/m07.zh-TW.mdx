<Step id="s1">

## 停止列舉配對

M5 以一項比值作結：採用 VG150 之 50 個 predicate 時，含十二個物件之影像約每一千次判定之中僅一次為正例；偵測器保留 80 個框時，約每四萬五千次之中僅一次。單階段方法正視此一事實，直接預測三元組的集合，全程不進行任何配對列舉。其所借用的機制源自 DETR：固定數量的 query，每一 query 至多輸出一項預測，並以逐影像計算的二分圖指派與標準答案配對。

此一改變並非速度上的最佳化。它將「這些配對之中何者具有關係」替換為「本影像之中有些什麼」，而兩個問題的失效模式並不相同。

</Step>

<Step id="s2">

<Intuition>

模型輸出的是無序集合，而損失函數必須知道各預測分別對應哪一項標註。故先計算使總成本最小的指派，再透過該指派施加損失。其後全部行為均取決於 query 數量 $q$，而 $q$ 於訓練之前即已選定。

</Intuition>

<Formal>

$$
\hat\sigma=\arg\min_{\sigma}\sum_{i=1}^{\lvert G\rvert}\left[w_c\,\mathcal{L}_{\text{cls}}(i,\sigma(i))+w_b\,\mathcal{L}_{\text{box}}(i,\sigma(i))\right]
$$

</Formal>

<Worked>

$$
\begin{aligned}
\hat\sigma &= \arg\min_{\sigma}\ \sum_{i=1}^{\lvert G\rvert}\mathcal{L}\bigl(i,\sigma(i)\bigr),
\qquad \mathcal{L}=w_c\mathcal{L}_{\text{cls}}+w_b\mathcal{L}_{\text{box}}\\
\text{cost} &= O(q^3) \ \text{by the Hungarian algorithm, } q=\text{number of queries}
\end{aligned}
$$

</Worked>

<Implications>

$$
\begin{gathered}q<\lvert G\rvert \;\Rightarrow\; \lvert G\rvert-q \text{ ground-truth triplets are unreachable: recall is capped at } q/\lvert G\rvert.
\\ q\gg\lvert G\rvert \;\Rightarrow\; q-\lvert G\rvert \text{ slots train only against } \varnothing \text{ and stay undertrained.}
\\[4pt]
\text{SpeaQ answers with groupwise specialization; Hydra-SGG with one-to-many assignment.}\end{gathered}
$$

上述兩項界限宜視為訓練無法消除的設計拘束。query 過少，則召回率存在模型無論如何學習均無法突破的上限；query 過多，則多數 query 於訓練期間僅見到無物件類別，因而始終無法發揮作用。

此即本單元標題中後段各方法存在的理由。SpeaQ 將 query 分組專門化，使單一 query 負責某一類關係而非某一位置；Hydra-SGG 則將單一預測指派給多個標準答案三元組，藉此鬆綁「一 query 一答案」此一造成長尾訓練不足的規則。

另須留意 $q$ 對速度與準確度前緣的影響：Hungarian 步驟的複雜度為 $q$ 的三次方，故無法僅以增大 $q$ 同時迴避兩種失效模式。

</Implications>

</Step>

<Step id="s3">

## 七種設計，及其各自推動之處

**FCSGG** 預測關係親和場——一組稠密的逐像素向量場——而非離散配對。其為文獻中速度最快、準確度最低者，構成前緣的左端。

**RelTR** 將主體與客體 query 耦合，使單一 query 同時承載三元組的兩端。

**SGTR** 於實體提案與 predicate 提案之間建構二分圖，使配對由學習而得，而非經由列舉或假定。

**EGTR** 自偵測器本身的解碼器注意力中萃取關係；其觀察在於偵測器原已計算物件間的交互作用，其後卻予以捨棄。

**DSGG** 將整體視為單一的圖預測問題；**SpeaQ** 依組別專門化 query；**Hydra-SGG** 採用一對多的混合指派；**REACT** 則為近期的效率取向成果。

持平的總結是：前緣於速度上大幅推進，於準確度上則推進有限。閱讀單階段方法的表格時，宜先讀延遲欄位。

</Step>
