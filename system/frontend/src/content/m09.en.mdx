import { Formal, Implications, Intuition, Worked } from './math/Parts';

<Step id="s1">

## The vocabulary was always the problem

M1 said the predicate vocabulary is whatever annotators wrote. M11 will say a frontier VLM scores
0.032 because it does not know which words are allowed. Open-vocabulary work sits between those
two observations: it asks what happens when a model must name something it was never trained to
name.

The experimental design is a holdout, and the holdout is where the subtlety is.

</Step>

<Step id="s2">

<Intuition>

Split the class set into base and novel, train on base only, and report on each part separately.
The trap is in what "train on base only" costs: an image containing one novel class must leave the
training set entirely, so the training data shrinks faster than the fraction held out.

</Intuition>

<Formal>

$$
\mathcal{C}=\mathcal{C}_{\text{base}}\sqcup\mathcal{C}_{\text{novel}},\quad \mathcal{P}=\mathcal{P}_{\text{base}}\sqcup\mathcal{P}_{\text{novel}};\qquad R \text{ reported on each part separately}
$$

</Formal>

<Worked>

$$
\begin{aligned}\mathcal{C}=\mathcal{C}_{\text{base}}\sqcup\mathcal{C}_{\text{novel}},&\qquad \mathcal{P}=\mathcal{P}_{\text{base}}\sqcup\mathcal{P}_{\text{novel}}\\\mathcal{D}_{\text{train}}&=\bigl\{I : \text{every }t\in G_I\text{ uses base classes only}\bigr\}\end{aligned}
$$

</Worked>

<Implications>

$$
\begin{gathered}\text{Holding out a class removes every image containing it, so }\lvert\mathcal{D}_{\text{train}}\rvert\text{ falls faster than the holdout fraction:}\\ \text{VG150}\to 50{,}107\ (\text{OvD}),\quad 44{,}333\ (\text{OvR}),\quad 36{,}425\ (\text{OvD+R}).\\[4pt]\text{Report }R\text{ on base and novel separately; one number hides which half failed.}\\ \text{Verified, Swin-T novel split: OvD }18.14,\quad\text{OvR }13.45,\quad\text{OvD+R }9.20\text{ (relations)}.\\[4pt]\text{Withholding }\textit{relations}\text{ hurts far more than withholding objects:}\\ \text{object names transfer through a pretrained text encoder, relations do not.}\end{gathered}
$$

Three things follow, and the third is the one that changes how you read the literature.

**Report base and novel separately.** One averaged number hides which half failed, and the halves
fail for different reasons.

**The three regimes are not comparable with each other.** OvD holds out object classes, OvR holds
out relation classes, OvD+R holds out both, and each shrinks the training set differently. A method
evaluated under OvD is not in competition with one evaluated under OvD+R.

**Withholding relations hurts far more than withholding objects**, and the reason is the honest
finding of this module: an object name transfers through a pretrained text encoder, which has seen
the word in a caption somewhere. A relation does not. There is no pretraining corpus in which
`meshed with` is grounded to an image the way `wrench` is.

That asymmetry is why VS³ inherits a visual-semantic space from a grounding model, why OvSGTR
aligns nodes and edges separately, and why PGSG generates novel predicate *words* rather than
selecting from a list.

</Implications>

</Step>

<Step id="s3">

## The leakage that invalidates the setup

A model whose grounding pretraining corpus already contains the held-out classes has not been
tested on novel classes at all. This is not hypothetical: the pretraining sets used by the
grounding models these methods build on are large, web-scraped and not disjoint from Visual
Genome.

When you read an open-vocabulary result, the question to ask is not how well it did on novel
classes. It is whether the novel classes were novel to the *whole pipeline*, including everything
inherited from the backbone. Most papers cannot answer this, and the ones that discuss it deserve
more credit than their numbers alone suggest.

</Step>

<Step id="s4">

## Checkpoint

A paper reports novel-class relation recall of 14.2 under OvR and compares it with a competitor's
19.6 under OvD. Say what is wrong with the comparison, and state which of the two numbers you
would expect to be larger before knowing anything about either method.

</Step>
