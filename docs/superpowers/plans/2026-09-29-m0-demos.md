# M0 demonstrations: D-T and D-V Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add two motivating demonstrations to M0, between s6 and the L1 lab: D-T, the traditional detect, enumerate and classify pipeline, and D-V, IndVisSGG end to end, both run on the same ten frames of one IndustReal clip, recorded once and replayed offline.

**Architecture:** Three backend scripts produce the data on the NAS: `cut_demo_m0.py` cuts the clip and ten frames, `record_demo_traditional.py` runs Faster R-CNN and a frequency prior into ten measured `SceneGraph` files, `record_demo_indvissgg.py` records fifty Claude exchanges through the fixed provider, and `build_demo_m0.py` derives the two JSON files the frontend reads. The frontend adds a `demo` step kind beside `playground`: `<Demo id part/>` resolves through `frontend/src/demos/mounts.tsx` to one component per demo that renders its part, over pure functions in `demos/logic.ts`. `content_lint.mjs` gains five rules over the new kind.

**Tech Stack:** Python 3.12 (py12), FastAPI app modules, torch 2.10.0+cu128 and torchvision 0.25.0+cu128 (recording only), `anthropic` SDK (recording only), ffmpeg 8.1; TypeScript, React 19, Vite 8, MDX, vitest (jsdom), Playwright (Chromium), Node ≥ 22.12.

**Spec:** `docs/superpowers/specs/2026-09-29-m0-demos-design.md` (commit `f250938`). It builds on the M0 playground design (the step contract), the split design (parts, D96) and contracts §2.4.

  - `CLASS_SYNONYMS: dict[str, str]`: COCO label to slice class, where the names differ (`"dining table": "table"`, `"cell phone": "phone"`, `"tv": "screen"`); a COCO label equal to a slice class maps to itself.

  - `slice_classes(graphs) -> set[str]`; `map_class(label: str, classes: set[str]) -> str | None`.
  - `frequency_table(graphs) -> dict[tuple[str, str], Counter[str]]` over every relationship row, keyed by (subject `names[0]`, object `names[0]`).
  - `most_frequent(graphs) -> str`.
  - `classify(subject: str | None, obj: str | None, table, fallback: str) -> tuple[str, Literal["prior", "fallback"]]`: argmax count, ties broken by predicate name ascending; an unmapped class or an unseen pair gives `(fallback, "fallback")`.
  - `Detection = TypedDict("Detection", {"label": str, "score": float, "box": tuple[float, float, float, float]})` with the box as x, y, w, h in pixels.
  - `to_scene_graph(image_id: str, width: int, height: int, detections: list[Detection], table, classes: set[str], fallback: str, generated_at: str) -> SceneGraph`: objects in detection order, `object_id` 0 to n − 1, `names=[label]`; one relationship per ordered pair (i ≠ j), in (i, j) order, predicate from `classify`, `score=None`; provenance `kind="model"`, `fidelity="measured"`, `model=MODEL`, `generated_at`, and a `note` naming the threshold, the prior's 80 frames and the fallback. `dataset="mini-isg"`.
  - `detect(path: Path) -> list[Detection]`: torchvision `fasterrcnn_resnet50_fpn(weights=FasterRCNN_ResNet50_FPN_Weights.COCO_V1)`, eval mode, CUDA when available, scores ≥ `THRESHOLD`, labels from `weights.meta["categories"]`. torch imported inside.
  - `SCORES = DATA_DIR/"demos"/"m0"/"detections.json"`: `{image_id: [score, …]}` in object order. It lives outside `OUT` because the audit reads every `*.json` under `OUT` as a `SceneGraph`, and the schema forbids a score on an object.
  - `main()`: every manifest frame through `detect` and `to_scene_graph`, one file per frame under `OUT`, and the scores to `SCORES`; prints the torch build, the device, the per-frame detection counts and the distinct labels.
